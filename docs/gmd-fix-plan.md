The sequential AOI buffers must not be added together as simultaneous usage.

Memory findings must retain these distinctions: `BJOBS`, custom-model buffers, and `_sessions` have intentional but unbounded retention; raster/preview/encoding/ZIP work creates temporary allocation pressure; view URLs have a missing explicit release path. A WeakMap does not revoke a URL, but toggling the same clip reuses its existing URL. The evidence does not confirm a monotonic native/GPU leak, and default CPU-backed ONNX outputs must not be called leaked GPU tensors without profiling.

Shared acceptance and compatibility rules apply to every entry. Preserve relative URLs under `/GeoMap-Detector/`, static worker/assets delivery through the existing `frontend/` Pages artifact, the existing model export in `pages.yml`, WebGPU-to-WASM fallback, drawing/editing, and native georeferencing. Keep model revision, chip size 1024, overlap 256, confidence, and suppression semantics unchanged during pure refactors. Golden decoded-output fixtures must match exactly for those refactors; real-inference comparisons must use the same provider and documented numeric matching tolerances. Precision/resolution changes require a held-out labelled set and an explicit per-class non-regression threshold established before the experiment. User-reported counts are a diagnostic example, not ground truth.

Benchmark targets are proposed release gates, not existing measurements or promised device-independent results. Record hardware, browser/runtime/model revisions, effective zoom, image size, cache state, and workload. Compare at least five cold and five warm startup samples and three controlled full-job repetitions, reporting median and p95 where sample size is useful. Repeated-view tests use at least 20 switches; model and memory soaks use at least 10 cycles after warm-up. Track owned resource counts and configured byte limits in addition to JavaScript heap, process/native memory, and GPU observations. A stable reusable runtime pool can remain above the initial footprint without being a leak.

Resource ownership contracts to establish incrementally:

| Resource | Owner and required end of life | Main tasks |
| --- | --- | --- |
| Raster, preview and training-chip canvases | Processing operation; release in `finally` after children finish; every allocation obeys the shared pixel/byte budget | GMD-005/GMD-006/GMD-012 |
| Tile ImageBitmaps | Acquiring tile consumer; close exactly once after draw or failure; close late arrivals after cancellation | GMD-012/GMD-013 |
| Overlay URL, layer and edit handles | Active clip view; dispose on replacement, hiding, removal, or job deletion after preserving the draft | GMD-003/GMD-004/GMD-009 |
| Download URL | Download action; retain long enough for the browser to consume it, then revoke; preserve the existing delayed-revoke behavior | GMD-004/GMD-015 |
| ONNX session and recoverable weights | Model manager in the processing context; hold leases during inference, release only idle sessions, preserve a reload source | GMD-010/GMD-007 |
| GPU tensors, if introduced | Follow runtime-owned versus user-owned buffer lifecycles; do not infer ownership from a JavaScript wrapper | GMD-010/GMD-017 |
| Fetches, retries, timers and pooled work | Per-job/view controller; shared tile requests additionally track consumers; cancel and drain before releasing shared state | GMD-012/GMD-013 |
| Worker and transferred buffers | Processing manager; worker owns accepted buffers; terminal acknowledgements precede normal worker teardown | GMD-007 |
| Job, clip, annotation and custom-weight records | Versioned storage layer; commit records before dropping the recoverable in-memory copy; deletion is explicit and scoped | GMD-008/GMD-009/GMD-016 |
| Tile cache and metadata cache | Disposable cache manager; bounded entries/bytes, compatible versions, separate from user records | GMD-013/GMD-014 |
| Export writers and destinations | Export operation; await writes for backpressure; finalize or abort/close on every terminal path | GMD-015 |

1. **Current status/evidence:** Planned. `_sessions` in `engine.js:194` grows without eviction, and only completed loads are cached. `app.js:263` keys custom weights by filename/size, retains each array buffer, and replaces class-name arrays without updating cached model metadata.
